财税产品 PRD 检查清单（初版）

  • 创建日期：2026-06-03
  • 来源类型：基于既有笔记提炼的原创工作清单
  • 提炼依据：
    • Notes/2026-06-02 - PRD 写作要点整理.md

使用场景

  • 写真实财税需求文档前，自查是否写到了可执行层。
  • 判断一个需求未来能否继续沉淀为 SOP、Skill 或 AI 辅助流程。

检查清单

1. 业务目标

  • 这个需求解决的是谁的什么问题？
  • 成功标准是什么？
  • 不做会带来什么业务后果？

2. 流程路径

  • 主流程是否完整写清？
  • 关键分支是否单独列出？
  • 是否明确了上下游角色、触发条件和结束条件？

3. 数据口径

  • 关键字段来源是否明确？
  • 口径是否唯一，是否存在多个统计版本？
  • 输入、输出、校验规则是否写清？

4. 异常分支

  • 哪些异常是高频的？
  • 异常出现后由谁处理、如何处理、何时升级？
  • 是否区分“可自动处理”和“必须人工介入”？

5. 验收标准

  • 验收是看页面结果、流程结果，还是数据结果？
  • 有没有可被测试和业务共同验证的判断标准？
  • 是否写清边界条件下的预期行为？

对 AI 落地的额外判断

  • 如果目标清楚但流程不稳定：先当 PRD / Prompt 辅助问题处理。
  • 如果流程稳定且重复：优先沉淀为 SOP 或 Skill。
  • 如果依赖系统读写、数据查询或动作执行：补系统连接，再谈自动化。
  • 如果目标、流程、工具、异常都比较成熟：再考虑 Agent 化。

当前边界

  • 这份清单目前来自 2 篇方法笔记的提炼，当前笔记中证据不足，尚未经过真实财税项目验证。
  • 后续应至少拿 1 个真实需求试跑一次，再补充缺失项和反例。
