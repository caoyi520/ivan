name: ai-weekly-evidence-report description: 生成 AI 使用反馈周报、作业包和可点击证据包时使用。适用于需要结合上周评分反馈、本周项目产出、自动化任务、Obsidian 知识库、可点击交互原型 HTML、截图证据、AGENTS/rules 规范和可复用经验沉淀的场景。

AI 周报证据包工作流

目标

把一周 AI 使用过程整理成“能打开、能核验、能复用”的提交包，而不是只写一份文字总结。

输出至少包含：

  • 周报正文 Markdown。
  • 可点击版 HTML 首页。
  • 项目文档、规范、截图和交互原型链接。
  • 可复用 Prompt、Skill、工作流经验。
  • 对上周反馈的逐项回应。

触发场景

用户要求生成、优化或提交：

  • AI 使用反馈周报。
  • AI 作业包。
  • 周报评分改进版。
  • 自动化任务复盘。
  • Obsidian / 第二大脑应用总结。
  • 可点击证据包。

工作流程

1. 读取反馈与目标

优先读取用户提供的评分反馈、作业要求、模板或示例。

提炼：

  • 上周得分与扣分点。
  • 明确要求补充的材料。
  • 本周需要突出的方法、工具或项目。

2. 扫描本周项目内容

优先检查：

  • git status --short
  • src/prototypes/
  • src/docs/
  • skills/
  • rules/
  • AGENTS.md
  • 用户明确提到的外部项目或自动化文档。

如果涉及 Obsidian，读取知识库目录结构和最近 7-14 天相关笔记，但只读取必要片段。

3. 组织周报正文

正文建议使用以下结构。详细模板见 references/report-outline.md。

  • 使用工具与 Skill。
  • 结合上周评分后的改进点。
  • 关键 Prompt / 核心思路。
  • 最终产出。
  • 效果评估。
  • 前后对比。
  • 经验沉淀。
  • 本周可提交附件。

写作原则：

  • 先写真实成果，再写方法总结。
  • 自动化任务按“触发器、任务、产物、失败兜底、人工介入点”描述。
  • Obsidian 按“输入层、知识层、原创判断层、项目层”描述。
  • 原型必须说明是否有可点击交互 HTML，不只放截图。

4. 生成交互原型 HTML

如果项目使用 Axhub Make：

  1. 运行项目构建生成 dist/prototypes/*.html。
  2. 将本周相关原型的 .html、.js 和 dist/assets/html-template-bootstrap.js 一起放进提交包。
  3. 在可点击版首页中链接到这些 HTML。

不要只交截图；截图用于验收证据，HTML 用于交互体验。

5. 生成截图证据

用浏览器打开本地原型，至少为本周重点原型各截一张图。

截图应放在：

  • src/docs/assets/<weekly-id>/
  • 或提交包内的 screenshots/

记录截图对应的页面、时间和用途。

6. 打包可点击版

提交包建议目录：

AI使用反馈周报_<date>_可点击版/
├── index.html
├── pages/
├── md/
├── screenshots/
├── prototypes/
│   ├── assets/
│   └── prototypes/
└── source-html/

打包前检查：

  • 首页所有链接存在。
  • Markdown 原文可打开。
  • 原型 HTML 能打开并可交互。
  • 截图能显示。
  • AGENTS.md 和关键 rules/ 已包含。

完整检查清单见 references/evidence-package-checklist.md。

验收要求

交付前必须完成：

  • 周报 Markdown 存在。
  • 可点击版 zip 存在。
  • 首页链接检查通过。
  • 至少一个交互原型 HTML 可打开。
  • 截图文件存在且非空。
  • 如果验收脚本失败，说明真实原因，不把脚本误判写成原型失败。

常用 Prompt

请先读取上周评分反馈，再扫描本周项目新增内容，按“评分改进点 → 本周产出 → 自动化任务 → Obsidian 应用 → 可点击交互原型 → 验收证据 → 经验沉淀”的结构生成 AI 使用反馈周报，并打包成别人解压后能直接点击查看的 HTML 作业包。
