临时迭代 1.11.1 需求评审工作台

📋 业务与功能

1.1 核心目标

本原型基于用户提供的 Axure 资料 https://axhub.im/ax10/35843f63742dfab4/#g=1，将“业财税合规&专业生产系统_需求文档 v1.11.1”整理为可搜索、可筛选、可逐项评审的需求工作台。目标用户为产品、研发、测试和业务验收人员，用于快速查看本次临时迭代涉及的页面、业务规则、影响范围与原型参考。

1.2 功能清单

  • 迭代总览：展示版本号、文档编号、需求项数量、重点场景与完成状态概览。
  • 主题导航：按 Axure 页面树中的 10 个迭代主题组织需求项，支持按主题切换。
  • 需求搜索与筛选：支持按标题、页面、关键规则搜索，并按需求状态筛选。
  • 需求卡片列表：展示需求标题、所属模块、影响端、关键规则数量、是否包含参考截图。
  • 详情评审区：展示当前需求的问题/方案、规则要点、功能说明、影响范围、验收关注点和原型截图链接。
  • 会话式评审栏：沉淀待确认问题、测试重点、数据口径提示，辅助跨角色评审。

1.3 交互要点

  • 点击左侧主题：过滤对应主题下的需求项，并选中第一条匹配需求。
  • 输入搜索词：即时过滤需求卡片，命中标题、所属页面、规则说明或影响范围。
  • 点击状态筛选：仅展示对应状态需求，支持全部、待评审、设计确认、开发就绪、需联调。
  • 点击需求卡片：切换右侧详情内容，并触发 onRequirementSelect 事件。
  • 点击“打开 Axure 原型”：新窗口打开用户提供的原始 Axure 链接，便于追溯。

2.2 数据来源

  • 数据类型：临时迭代需求清单
  • 数据源：用户提供的 Axure 在线原型，已抽取 26 个页面的标题、正文、右上角功能说明标注与参考图片链接
  • 关键字段：
    • id: 需求唯一标识
    • theme: 所属迭代主题
    • page: 对应 Axure 页面标题
    • title: 需求标题
    • status: 评审状态
    • module: 影响业务模块
    • scope: 影响端/页面范围
    • rules: 关键规则列表
    • functionNotes: Axure 标注中的功能说明分组
    • acceptance: 验收关注点列表
    • referenceImage: Axure 页面参考截图地址

2.3 内容示例

  • 工资表导入优化：姓名前后空格应忽略，允许工资表导入成功。
  • 国税/个税分别确税：申报数据汇总拆分国税、个税确税反馈状态，支持批量反馈、右栏完税截图/申报明细附件、历史数据兼容和税费信息列调整。
  • 国税/个税确税事项：国税事项仅展示国税待确税数据并增加完税截图；个税事项仅展示个税待确税数据并增加工资薪金申报明细附件下载。
  • 电子税务局无需申报：新增“申报开通”字段，枚举为需要申报/无需申报，并联动申报数据汇总、增值税、企业所得税、财务报表、生产国税进度、生产个税进度等页面。
  • 记账系统跳转：新增个税系统、社保系统入口，未开通时阻断提示，已开通时按账期和区域规则跳转。
  • 批量开通国税、个税：企业列表与事项页面增加批量导入入口、模板下载和上传校验。
  • 批量开通功能说明：点击批量开通电子税务局/个税扣缴端后，右栏展示对应内容；通过导入企业账密发起异步任务；附件仅允许上传 1 个，最多 10MB，格式限 xls、xlsx。
  • 失败原因优化：隐藏系统异常前缀，并基于关键词生成解决方案，未命中时展示通用解决方案，覆盖电子税务局登录相关页面。
  • 合规记账：数量为 0 且状态已完成时，凭证状态直接为“无需生成”，不触发 agent。

2.4 Axure 标注补充范围

  • 已点击 Axure 右上角说明入口，补充“会计中心-申报数据汇总”“国税税金确认”“个税税金确认”“电子税务局无需申报”“记账系统跳转”“批量开通国税/个税”“失败原因优化”“合规记账”等页面的完整功能说明。
  • 在原型详情区以“功能说明”分组展示标注内容，和“关键规则”“验收关注”分层，便于评审人员区分业务逻辑、页面表现和测试口径。
  • 未出现额外标注的主题保留 Axure 页面正文信息，例如工资表导入优化、账套迁移小计、企业数量 Tab、取消分配客服按钮。

🎨 布局与结构

3.1 整体布局

  • 布局模式：左侧窄导航 + 中央列表 + 右侧详情/协作栏的 B 端工作台。
  • 容器宽度：流式全屏，最小高度为视口高度。
  • 关键尺寸：
    • 左侧导航：桌面端 260px，显示主题和数量。
    • 中央列表：自适应宽度，卡片列表最小宽度 360px。
    • 右侧详情：桌面端 420px，固定展示当前需求详情。

3.2 响应式适配

  • 桌面端（≥1200px）：三栏布局同时展示。
  • 平板端（768-1199px）：左侧导航置顶为横向主题条，列表与详情两栏展示。
  • 移动端（<768px）：单列布局，主题、列表、详情上下排列，保证文字不溢出。

🎨 视觉规范

4.1 设计规范来源

设计规范来源：内置服务商设计规范 + frontend-design

说明：采用浅灰蓝背景、白色面板、细边框、小圆角与高密度信息组织；页面为 B 端需求评审工具，不使用营销式 hero。

4.2 自定义设计要点

自定义色彩：

  • 主操作蓝紫：#5b5bd6 - 当前主题、主按钮、选中态
  • 信息蓝：#2563eb - 规则与模块提示
  • 成功绿：#0f9f6e - 开发就绪、已确认状态
  • 提醒橙：#d97706 - 待评审、需联调状态

自定义尺寸：

  • 页面基础间距：16px
  • 面板圆角：10px
  • 卡片圆角：8px
  • 状态标签高度：22px

4.3 组件状态

  • 默认态（default）：白色面板、浅灰边框、文字层级清晰。
  • 悬停态（hover）：需求卡片边框加深并轻微上浮。
  • 选中态（selected）：卡片显示主色边框和左侧色条。
  • 空态（empty）：搜索无结果时展示清晰提示并保留筛选入口。
  • 加载态（loading）：当前原型为静态数据驱动，无远程加载态。

⚙️ Axure API 说明

5.1 事件列表（eventList）

事件名称 Payload 类型 触发时机 说明
onRequirementSelect string 点击需求卡片 返回当前需求 JSON 字符串
onThemeChange string 切换主题 返回当前主题名称
onOpenSource string 点击原型链接 返回 Axure 原始链接

5.2 动作列表（actionList）

动作名称 Params 类型 参数说明 功能描述
select_requirement string 需求 id 切换到指定需求
set_theme string 主题名称 切换到指定主题
reset_filters string 可为空 重置搜索、主题与状态筛选

5.3 变量列表（varList）

变量名称 类型 默认值 说明
selected_requirement object 第一条需求 当前选中的需求
active_theme string 全部主题 当前主题筛选
visible_count number 全量需求数量 当前筛选后的需求数量

命名规范：使用 snake_case（小写字母、数字、下划线）

5.4 配置项列表（configList）

配置项名称 类型 默认值 说明
title string 临时迭代 1.11.1 页面标题
subtitle string 业财税合规&专业生产系统需求评审 页面说明
