从 PRD 到 AI 执行的任务分层判断

  • 整理日期：2026-06-03
  • 来源类型：基于知识库既有笔记的二次判断
  • 关联来源：
    • Notes/2026-06-02 - AI 概念辨析：Prompt、Skill、MCP、Agent.md
    • Notes/2026-06-02 - PRD 写作要点整理.md

核心判断

  • 我最近关注的重点，不是“怎么把提示词写漂亮”，而是“怎么把业务任务写到可执行”。
  • 这个“可执行”至少包含 4 层：目标清楚、流程稳定、数据口径统一、异常分支可枚举。
  • 对财税产品工作来说，PRD 写作能力和 AI 落地能力并不是两件分开的事，底层都是在做对齐：
    • PRD 解决人与人的对齐。
    • Prompt / Skill / MCP / Agent 解决目标、流程、工具和执行的对齐。

隐藏关联

1. 我已经在用“流程工程”视角理解 AI

  • AI 概念辨析 里把 AI 能力拆成目标表达、流程固化、系统连接、自主执行。
  • PRD 写作要点整理 里强调最该结构化的是范例、流程、数据口径和边界条件。
  • 两篇笔记底层是同一套判断：业务规则如果没有被稳定表达，就既写不好 PRD，也用不好 AI。

2. 我反复强调的风险点已经收敛

  • 当前最稳定出现的高风险项是：
    • 流程路径
    • 数据口径
    • 异常分支
    • 验收标准
  • 这说明我真正担心的不是“功能缺不缺”，而是“规则有没有写到可执行、可校验、可复用”。

3. 任务是否该 Agent 化，本质上取决于规则成熟度

  • 如果目标只说得清、但流程不稳定，适合先用 Prompt 辅助。
  • 如果流程已经稳定、重复出现，适合先沉淀成 Skill。
  • 如果执行依赖真实系统数据或动作，才需要接 MCP。
  • 如果前面三层都具备，且任务可以拆成多步闭环，才值得讨论 Agent。

当前盲区

  • 我已经在总结方法，但还没有挂到自己的真实财税项目样本上。
  • /Projects 当前没有可直接关联的项目记录，当前笔记中证据不足，暂时无法判断哪个真实场景最适合先试点。
  • 如果继续停留在概念总结层，容易出现“知道怎么分析，但没有拿真实业务验证”的空转。

可行动结论

  1. 先不要泛泛讨论 Agent，先挑 1 个高频财税场景做样本。
  2. 这个样本至少补齐 5 个字段：业务目标、流程、数据口径、异常分支、验收标准。
  3. 用这个样本判断它更适合停留在 PRD、升级成 Skill、接 MCP，还是继续做 Agent 化。
