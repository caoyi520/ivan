# 导账系统产品需求文档（PRD）

## 1. 产品概述

### 1.1 产品定位

导账系统是一款面向财务软件切换、账套迁移和服务商实施交付的工作台工具。用户通过填写原财务软件账密授权系统读取账套数据，系统完成采集、校验、结果展示后，用户选择采集成功的数据导入新的财务软件。

### 1.2 目标用户

- 实施顾问：负责客户新财务软件上线和历史账套迁移。
- 企业财务管理员：提供原系统账密授权，确认采集结果和导入范围。
- 客户成功服务商：批量跟进迁移任务，处理采集失败、字段映射和导入异常。

### 1.3 产品目标

- 降低财务软件切换时的手工导账成本。
- 提升账套采集过程的透明度，让用户知道采集到了哪些数据。
- 通过状态和校验规则降低错误数据进入新系统的风险。
- 为服务商提供可复用、可评审、可追踪的导账流程。

## 2. 核心流程

```text
填写原财务软件账密
→ 系统验证权限
→ 进入账套数据采集
→ 展示采集结果和采集内容
→ 用户选择采集成功的数据
→ 导入新的财务软件
→ 输出导入任务与报告
```

## 3. 功能需求

### 3.1 原财务软件连接

**需求描述**：用户选择原财务软件，填写账套名称、管理员账号和密码，并选择采集范围。

**功能要求**：
- 支持选择原财务软件类型。
- 支持填写账套名称、账号、密码。
- 支持选择采集范围：基础资料、科目余额、会计凭证、固定资产、发票台账、辅助核算。
- 提示账号需具备只读或查询权限。
- 明示账密仅用于本次授权，不保存密码明文。

### 3.2 账套数据采集

**需求描述**：系统使用授权信息进入原财务软件，读取并结构化采集账套数据。

**功能要求**：
- 展示采集进度和当前采集步骤。
- 支持采集基础资料、科目体系、期初余额、凭证、固定资产、发票台账等。
- 采集过程中不修改原系统数据。
- 采集完成后进入结果页。
- 支持重新采集。

### 3.3 采集结果展示

**需求描述**：用户能看到采集成功、需处理、失败的结果分布，以及每类数据的明细。

**功能要求**：
- 展示成功数量、需处理数量、失败数量、总记录数。
- 表格展示采集内容、期间、记录数、金额、状态。
- 支持关键词搜索和状态筛选。
- 对需处理或失败数据展示原因。
- 成功数据状态为“采集成功”，可进入导入选择。

### 3.4 数据选择与导入

**需求描述**：用户选择采集成功的数据，并导入到新的财务软件。

**功能要求**：
- 仅采集成功的数据可勾选。
- 需处理和采集失败的数据不可直接导入。
- 支持选择目标财务软件。
- 导入前展示已选数据数量、目标系统、导入策略。
- 点击确认后创建导入任务。
- 导入策略默认：保留原凭证号，自动建立科目映射。

### 3.5 导账助手

**需求描述**：右侧助手根据当前采集状态提供导入建议和风险提示。

**功能要求**：
- 在连接阶段提醒权限和安全要求。
- 在结果阶段提示可直接导入的数据数量。
- 对科目映射缺口、插件授权过期等风险进行说明。
- 提供生成采集报告、处理科目映射、导入已选数据等快捷动作。

## 4. 业务规则

### 4.1 采集状态规则

| 状态 | 说明 | 是否可导入 |
|------|------|------------|
| 采集成功 | 数据完整且通过基础校验 | 是 |
| 需处理 | 数据已采集，但存在映射或校验问题 | 否 |
| 采集失败 | 数据未采集成功，通常由权限、插件或网络导致 | 否 |

### 4.2 导入选择规则

- 默认勾选全部采集成功的数据。
- 用户可以取消成功数据的勾选。
- 系统禁止勾选需处理或采集失败的数据。
- 未选择任何数据时，导入按钮禁用。

### 4.3 安全规则

- 密码不得明文落库。
- 采集过程只读，不写入原系统。
- 每次导账任务需记录操作者、时间、原软件类型、目标软件类型和导入范围。
- 导入前需生成可追踪的任务摘要。

## 5. 数据需求

### 5.1 输入数据

- 原财务软件类型。
- 原账套名称。
- 原系统账号和密码。
- 采集范围。
- 目标财务软件。

### 5.2 输出数据

- 采集结果汇总。
- 采集内容明细。
- 异常和处理建议。
- 用户选择的导入数据。
- 导入任务信息。

### 5.3 采集内容字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 数据项唯一标识 |
| `type` | string | 数据类型 |
| `name` | string | 采集内容名称 |
| `period` | string | 所属期间 |
| `count` | number | 记录数量 |
| `amount` | number | 金额合计 |
| `owner` | string | 所属模块 |
| `status` | enum | success / warning / failed |
| `issues` | string[] | 异常说明 |

## 6. 非功能需求

- 可用性：核心路径不超过三步，用户能明确知道下一步动作。
- 可靠性：采集失败时需保留失败原因，允许重新采集。
- 可追溯：导入任务、采集结果、用户选择范围均可记录。
- 安全性：账密加密传输，不保存密码明文。
- 兼容性：优先适配桌面端服务商工作台，兼顾平板宽度。

## 7. 验收标准

- 用户可以填写原财务软件账密并进入采集状态。
- 采集完成后可以看到成功、需处理、失败和总记录数。
- 用户可以查看采集内容明细和异常原因。
- 用户只能选择采集成功的数据。
- 用户选择数据后可以创建导入新财务软件的任务。
- 页面符合服务商设计规范：浅灰蓝背景、白色面板、紫色主操作、右侧助手栏、高信息密度。
